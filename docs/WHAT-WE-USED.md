## Settings we changed

- Turborepo and Next.js anonymous telemetry turned off (privacy).
- Next.js "Cache Components" turned off (not needed for this app yet).
- Claude Code **hook** (`PostToolUse`, matcher `Write|Edit`) runs Prettier on files Claude edits inside this project; uses `jq` to read the file path. Lives in `.claude/settings.json`. Needs `/hooks` opened once after the file is first created.
- Claude Code **skill** `/update-what-we-used` (`.claude/skills/update-what-we-used/SKILL.md`) updates this file when something new is added. Needs `/reload-skills` once after the folder is first created.
- The 3D viewport is **browser-only**: `Viewport.tsx` is a Client Component (`"use client"`), loaded by `ViewportLoader.tsx` with `next/dynamic` and `ssr: false`. Next.js only allows `ssr: false` inside a Client Component, so `page.tsx` stays a Server Component.
- Diagrams live in `docs/diagrams/` as self-contained HTML with inline SVG (open in any browser). `dev-workflow.html` (how an edit reaches GitHub) and `architecture.html` (the system, one edit between two users, code layout). Whiteboard-style SVGs per feature: `projects-and-scenes.svg`, `edge-loops.svg`, `bevel-and-edge-extrude.svg`, `thicken-modifier.svg`, `project-home.svg`, `uvs-and-seams.svg`, `four-view-peek.svg`, `edit-tools.svg`, `testing-flow.svg`, `hide-and-show.svg`, `simplify.svg`, `shrinkwrap.svg`.
- `create-next-app` generated `AGENTS.md` (notes for coding agents; points to the docs bundled in `node_modules/next/dist/docs/`).

- Git **pre-push hook** (`.husky/pre-push`, via Husky): runs `pnpm check-types && pnpm lint && pnpm test && pnpm build` before every `git push`, including from GitHub Desktop, and blocks the push if one fails. Skip once from a terminal with `git push --no-verify`. `pnpm install` switches it on (root `prepare` script). It adds Homebrew and fnm to `PATH` itself because GitHub Desktop does not load your shell profile.
- **Transform gizmo**: drei `TransformControls` (no new library) on the selected object. It moves the three.js object while you drag and writes the transform to the store once on mouse up (one drag = one change, ready for undo). `OrbitControls` has `makeDefault`, so drei pauses orbiting during a drag. Shortcuts: W / E / R mode, X snap, Esc deselect.
- **Autosave and restore** (`apps/web/src/persistence/`): the scene is saved in the browser's own database, IndexedDB (no library: a small promise wrapper in `idb.ts`), 500 ms after the last change, and restored when the page opens. Imported files go in the same database (`IndexedDbAssetStorage`). What is read back is checked with Zod (`parseSavedScene` in `packages/shared`); unreadable data is copied to a backup first. Saving starts only after the restore has finished. A status ("All changes saved") sits in the top bar and the browser asks before the page is left with unsaved changes. Tested with `fake-indexeddb` 6.2.8 (a dev-only test helper that imitates IndexedDB in Node; Apache-2.0).
- **Projects and scenes** (`packages/shared/src/project.ts`, `apps/web/src/store/projectStore.ts`, `SceneTabs.tsx`): no new library. A project is a Zod-checked list of scenes; the open scene stays in the scene store and the others are "parked" in `projectStore` with their own selection and undo history. The autosave writes the whole project as one IndexedDB record (`IndexedDbProjectRepository`); a scene saved by an older version is wrapped as a one-scene project. Unity comparison: a project is like a Unity project and each scene like a `.unity` scene file, but switching is instant because the other scenes stay in memory. The `.sceneroom` file (`sceneFile.ts`, version 2) now holds the whole project, with each model or mesh stored once; old one-scene files still open. Imported models are listed project-wide (`collectProjectModels`), and **prefabs** (`prefab.ts`, `libraryActions.ts`, `prefabEditing.ts`, `PrefabSection.tsx`, the Assets tab) are linked copies of an object that can be placed in any scene; double-click one to open it in a scene of its own (like Unity's prefab mode) and every copy follows. Diagram: `docs/diagrams/projects-and-scenes.svg`.
- **Copy, cut, paste and the right-click menu**: Copy takes the selected objects and everything inside them as a snapshot (`copyToClipboard`) and Paste makes NEW objects from it (`pasteFromClipboard`: new ids, same structure, numbered names, one step along each time). **Cut only marks** the objects (greyed in the list and faded in the 3D view; a grey wireframe box for imported models); **pasting a cut MOVES the same objects** (`moveToParent`, keeping their place in the 3D view) and empties the clipboard. Where a paste goes is decided by `pasteTarget`: plain Paste = inside the single selected object (`resolveAutoPlacement`; beside it if it is what was copied or cut, top level if nothing is selected), Ctrl/Cmd + Shift + V or "Paste beside" = next to the selected object, "Paste at top level" = top level. Locked parents and pasting an object into itself are refused with a message. Escape cancels a cut. The clipboard is in memory only (not the system clipboard). The menu (`ContextMenu.tsx`) opens on a right-click of an object in the 3D view (a ray from the camera, `ViewportContextMenuController.tsx`) or of a row in the scene list and acts on the selection. `apps/web/vitest.config.ts` lets tests use the `@/` shortcut.
- **Selecting rows in the list**: Shift + click selects the rows between the anchor (the last row clicked, or the only selected object) and the clicked row (`rangeBetween`, pure and tested); Ctrl/Cmd + click adds or removes one row.
- **Assets panel** (the "Assets" tab of the left panel: `AssetsPanel.tsx`, pure rules in `packages/shared/src/assetOps.ts`): lists the imported files of the scene with triangles, size and how many objects use each (`assetUsageCounts`). Place another copy (`placeAsset`), rename the file (`renameAsset`), keep a source / licence note (`setAssetNote`), delete the file together with the objects using it (`removeAsset`, one undo step). Each file has a thumbnail (`apps/web/src/assets/thumbnail.ts`: a plain three.js `WebGLRenderer` draws a copy of the model once into a 128 px picture, `toDataURL`, framing from `thumbnailFraming`) and the whole card can be dragged: dropping it on the 3D view (browser drag and drop, `AssetDropController`, `groundHit`) places the model on the ground at the pointer, with a see-through preview (`AssetPreview.tsx`) while dragging. The rules are pure functions with tests; the store actions only call them and record undo steps. No new libraries.
- **Surface and shading** (`SurfaceSection.tsx`, `materialSchema` in `packages/shared/src/scene.ts`): each object has a `material` section (roughness, metalness, glow colour and strength, opacity, double-sided, flat shading, cast and receive shadow). The Inspector section edits it through `setNodeMaterial` (cleaned by `sanitizeMaterialChange`, undo steps only for real changes); `SceneNodes.tsx` passes the values to three.js's `meshStandardMaterial` and shadow flags. Shadows: `shadows` on the R3F `Canvas`, a shadow-casting directional light and a `shadowMaterial` ground in `Viewport.tsx`. Older saved scenes are migrated by `migrateLegacyMaterial`. No new libraries.
- **Lights** (`packages/shared/src/lights.ts`, `LightObject.tsx`, `LightSection.tsx`): three object kinds (directional, point, spot) with a `light` section. Rendered with three.js's `directionalLight`, `pointLight` and `spotLight` through React Three Fiber; a new light is aimed with `aimRotation` (a small rotation-matrix to Euler conversion, tested). Settings are cleaned by `sanitizeLightChange`; the store has `addLight`, `setNodeLight` and `previewNodeLight` (one undo step per slider drag). The Inspector reuses `ValueSlider` and `ColorRow`. No new libraries.
- **Environment** (`packages/shared/src/environment.ts`, `SceneEnvironment.tsx`, `EnvironmentPanel.tsx`): the world settings live in `scene.environment` (Zod, defaults). `SceneEnvironment` (inside the Canvas) draws the background (a colour, or a canvas-gradient sky as an equirectangular `CanvasTexture`), builds the reflection picture with three.js's `PMREMGenerator` from `RoomEnvironment` (the "studio", `three/examples/jsm/environments/RoomEnvironment.js`) or from the sky texture, and sets fog. Objects read the picture from a small store (`environmentTexture.ts`) to apply their own Reflection strength. The base ambient light and sun read the settings too. No new libraries and no downloads.
- **Modifiers** (`packages/shared/src/modifiers.ts`, `shapeGeometry.ts`, `ModifiersSection.tsx`): each built-in shape has `segments` and a list of modifiers (bend, twist, taper). `deformPoints` (pure maths on plain number arrays, tested) moves the points; `buildShapeGeometry` creates the three.js geometry (`BoxGeometry` etc. with segment counts), applies it with `BufferAttribute`, then `computeVertexNormals`. The store has add, remove, set, preview, move and segment actions (one undo step per slider drag). No new libraries.
- **More modifiers** (`packages/shared/src/modifiers.ts`): Stretch, Noise, Mirror and Array join Bend, Twist and Taper. `deformMesh` works on points and triangles (typed arrays) so mirror and array can add geometry; noise is value noise from an integer hash (`Math.imul`), written by hand (no noise library). Still pure maths, tested with exact points. No new libraries.
- **Scene files** (`packages/shared/src/sceneFile.ts`, `apps/web/src/sceneFile/`): Save and Open pack the scene and its model files into one `.sceneroom` file (format in `docs/SCENE-FILE-FORMAT.md`). Written with plain `Uint8Array` and `DataView` (no zip library), the scene checked by the same Zod schema as the autosave, each model checked as a GLB and against its SHA-256 id. Download with a `Blob` and a temporary link; opening with `File.arrayBuffer()`. No new libraries.
- **GLB export** (`apps/web/src/export/`): `buildExportScene` builds a clean three.js scene from the scene data (shapes via `buildShapeGeometry`, `MeshStandardMaterial`, three.js lights, copies of the loaded models) and three.js's `GLTFExporter` (`three/examples/jsm/exporters/GLTFExporter.js`, with the `KHR_lights_punctual` extension) writes the `.glb`; `download` hands it to the browser. Tested by reading the written file's JSON. No new libraries.
- **Editable meshes** (`packages/shared/src/meshData.ts`, `meshOps.ts`, `apps/web/src/assets/meshStorage.ts`, `apps/web/src/mesh/bakeMesh.ts`): the "mesh" object kind, with its points and triangles stored as a binary blob (`DataView` and typed arrays, checked completely when read) in the same asset storage as imported models, under a SHA-256 fingerprint. "Apply modifiers" and "Convert to mesh" bake an object into one (`bakeToMesh`). Edits will make new blobs, which keeps undo cheap. No new libraries.
- **Edit mode** (`packages/shared/src/meshEdit.ts`, `apps/web/src/meshEdit/`, `MeshEditor.tsx`): select and move the points of an editable mesh. Wire lines and point dots are three.js `LineSegments` and `Points` that share the mesh's own position attribute; clicking and boxes use screen-space maths (pure, tested); the move handle is drei's `TransformControls` on an invisible pivot at the middle of the selected points; a finished drag stores a new mesh version. No new libraries.
- **Fly camera** (`packages/shared/src/fly.ts`, `FlyController.tsx`): hold the right mouse button in the 3D view and press W A S D to fly (Q down, E up). The movement (directions, speed from the distance to the target, a capped step per frame) is a pure, tested function; the controller moves the camera and drei's `OrbitControls` target together, and puts the orbit point back when the button is released. Unity comparison: right-click fly mode in the Scene view. No new libraries.
- **X-ray in edit mode** (`visibility.ts`, `surfaceOffset.ts`, `pickEdge.ts`): lines and points on faces the camera cannot see are hidden by drawing the edit overlay with the depth test on while the mesh is pushed back a little (`polygonOffset`), and picking uses a ray from the camera to each candidate point or edge middle; an X-ray button and Alt + Z turn it off. Unity comparison: Scene view's shaded vs wireframe-on-top. No new libraries.
- **Extrude settings** (`extrudeFaces` options in `packages/shared/src/meshEdit.ts`, `ExtrudePanel.tsx`, `OperationField.tsx`): an extrusion can be cut into bands, tapered and twisted (pure, tested: heights, widths and wall directions are checked). The panel shows a change while a slider is dragged (the geometry on screen is replaced; nothing is stored) and stores the result once when it is let go, in place of the extrusion made before (one undo step). Unity comparison: ProBuilder's Extrude settings. No new libraries.
- **Four-view peek** (`packages/shared/src/views.ts`, `PeekRenderer.tsx`, `peekRender.ts`, `BigViewController.tsx`, `PeekOverlay.tsx`, `usePeekKeys.ts`): hold Space to draw the scene four times into one canvas (the renderer's viewport and scissor per tile; a frame callback with priority above 0 takes over drawing from React Three Fiber), with three orthographic side cameras framed on the selection and the normal camera for the fourth; letting go opens a tile as the big view (a pinned flat camera whose orbit controls can only zoom). The maths is pure and tested; the drawing is tested with a stand-in renderer. Unity comparison: the Scene view's gizmo view switcher and Maya's four-view layout on the Space bar. No new libraries.
- **Edge creases** (`packages/shared/src/creases.ts`, mesh data version 2 in `meshData.ts`, the vertex and edge rules in `subdivide.ts`, `creaseSelectedEdges` in `editOperations.ts`): edges marked as sharp are stored with the mesh and make the Smooth modifier keep them crisp (semi-sharp creases, as in Pixar's OpenSubdiv). Pure and tested with exact positions. Unity comparison: ProBuilder / Blender's edge crease (Shift + E in Blender). No new libraries.
- **Smooth (subdivision) modifier** (`packages/shared/src/subdivide.ts`, the modifier list in `modifiers.ts`, one slider in `ModifiersSection.tsx`): Catmull-Clark subdivision on the topology layer (welded vertices, face points, edge points, the vertex rule, the border rule), pure and tested with exact positions (a cube corner lands 5/18 of the way out) and counts. It is a normal modifier, so it is non-destructive, can be reordered or switched off, and Make mesh bakes it. Unity comparison: a Subdivision Surface (as in ProBuilder's Subdivide or a Blender Subdivision Surface modifier). No new libraries.
- **Thicken (Solidify) modifier** (`packages/shared/src/solidify.ts`, the modifier list in `modifiers.ts`, one slider in `ModifiersSection.tsx`): copies the surface, moves the copy against the way it faces (by a share of the shape's size), turns it inside out and joins the two along every open edge. A plane becomes a slab, an open shape a shell, a closed shape gets a hollow inside. Even thickness (longer push at corners, angle-weighted normals) keeps walls the same thickness; tested with exact volumes. Unity comparison: Blender's Solidify modifier (ProBuilder has no modifier for it). No new libraries.
- **Project overview** (`packages/shared/src/projectOverview.ts`, `ProjectDialog.tsx`, `renameProject` in `projectStore.ts`): a dialog from the project name with the project's name (renamable), each scene's object, light, prefab-copy and triangle counts, and removal of imported models no scene or prefab uses. Plain React and Tailwind, no dialog library. Unity comparison: the Project window's summary plus Unity's "Remove unused assets". No new libraries.
- **Project home screen** (`apps/web/src/components/home/`, `persistence/projectLibrary.ts`, `packages/shared/src/projectIndex.ts`, `app/page.tsx`, `app/p/[projectId]/page.tsx`): a grid of project cards (picture, name, last edit, scenes) before the editor, with new / open file / rename / duplicate / export / delete. Many projects in IndexedDB (an index, one record per project, one picture per project), the editor on its own address per project, pictures from the 3D canvas. Next.js dynamic route (`params` is a Promise in this version; read in a server page and passed down). Unity comparison: the Unity Hub project list. No new libraries.
- **Inset** (`extrudeFaces` with a distance of 0 and a smaller scale; the Inset button and key I): the same pure operation as Extrude with different starting values, so it has the same live panel (Depth, Face size, Divisions, Twist) and one undo step; a negative depth pushes in. Unity comparison: ProBuilder's Inset Face. No new libraries.
- **Loop cut** (`packages/shared/src/loopCut.ts`, `LoopCutPanel.tsx`, `pickEdge.ts`): pick an edge, take the ring of edges through it (the topology layer), and split every square of the strip with new points on the crossed edges. Pure and tested (boxes, planes, refusals, triangle winding, sharp edges). The tool, its hover preview and panel reuse the Extrude settings machinery (show while dragging, store once on release, one undo step). Unity comparison: ProBuilder's Loop Cut / Blender's Ctrl + R. No new libraries.
- **Bevel** (`packages/shared/src/bevel.ts`, `BevelPanel.tsx`, `bevelSelectedEdges` in `editOperations.ts`): cuts each selected edge back on both faces, joins the cuts with a strip (a quadratic curve for more than one segment) and fills the corners where bevelled edges meet. Pure and tested (single edge, all twelve cube edges, refusals, width limit); same preview and one-undo-step panel as loop cut. Unity comparison: ProBuilder's Bevel / Blender's Ctrl + B. No new libraries.
- **Fix-up tools** (`packages/shared/src/meshTools.ts`, the "Fix up" row in `EditModeBar.tsx`, `editOperations.ts`): Merge at centre, Weld close points (grid of cells, union-find), Flip normals, Fill hole (border rings found from directed edges), Bridge (two rims of equal size, lined up by shortest total length). Pure and tested (closed, consistently wound results). Unity comparison: ProBuilder's Merge Vertices, Weld, Flip Normals, Fill Hole and Bridge Edges. No new libraries.
- **Selection tools** (`packages/shared/src/selectionOps.ts`, the "Adjust" row in `EditModeBar.tsx`, `selectionTools.ts`): More, Less, Invert, Similar and Outline (the edges round the selected faces, for the rim of a lid) on the derived topology; pure and tested on planes and a cut cube. Unity comparison: ProBuilder's Grow / Shrink / Invert / Select by similar. No new libraries.
- **Divide faces** (`packages/shared/src/divide.ts`, `DividePanel.tsx`, `divideSelectedFaces` in `editOperations.ts`): evenly cuts squares and triangles into smaller ones (bilinear and barycentric grids, shared edge points), keeps the shape, carries creases, with the live panel (Cuts) of the other edit tools. Unity comparison: ProBuilder's Subdivide. No new libraries.
- **UV checker and UV data** (`packages/shared/src/meshData.ts` version 3, `ShapeMesh.uvs`, `components/viewport/checkerTexture.ts`, `checkerView.ts`, `SurfaceMaterial.tsx`): UVs stored with a mesh (optional, format version 3), carried from built-in shapes into meshes, kept by the point-moving modifiers and by Mirror and Array, written to GLB as `TEXCOORD_0`, and a checkerboard view of the selected objects drawn with a three.js `CanvasTexture`. Unity comparison: a mesh's UV channel and the UV checker texture many artists use. No new libraries.
- **UV map through the edit tools** (`uvCarry.test.ts`, and the UV handling in `divide.ts`, `loopCut.ts`, `bevel.ts`, `meshEdit.ts`, `meshTools.ts`, `edgeExtrude.ts`, `solidify.ts`): every edit tool except Smooth keeps or works out the UVs of the points it makes (interpolated for Divide and Loop cut, copied for Extrude and Thicken, renumbered for Delete, Merge and Weld). Pure and tested with a map that is a straight-line function of position. Unity comparison: ProBuilder keeping UVs through its operations. No new libraries.
- **Seams** (`packages/shared/src/seams.ts`, mesh format version 3 flag bit 1, `seamSelectedEdges` in `editOperations.ts`, the UV row in `EditModeBar.tsx`, `setSeams` in `editOverlay.ts`): edges marked as the cuts for flattening a surface into a UV map; stored with the mesh, drawn in red in edit mode and carried through the edit tools the same way creases are. Pure and tested (marking, clearing, storing, Divide, Loop cut, delete, Mirror, Array). Unity comparison: Blender's Mark Seam (ProBuilder has no seams; its UV editor cuts by selection). No new libraries.
- **Shrinkwrap** (`packages/shared/src/surfaceSnap.ts`, `apps/web/src/meshEdit/shrinkwrap.ts`, the Wrap onto list and Shrinkwrap button in `EditModeBar.tsx`): no new library. The main mode pushes every point out from the middle of the target until it meets the target's surface (ray against triangle, Möller–Trumbore, over a uniform grid), after the mesh's middle is moved onto the target's middle so a mesh beside the target still covers it; points whose ray misses fall back to the closest spot on a triangle (Ericson's method), checked against a brute-force search in the tests. In the app the target is any shown object: the target's geometry and `matrixWorld` come from the three.js object (`meshRegistry`), points are carried into the target's space with the inverse matrix and back. Only positions change, so UVs, seams and creases stay and a big mesh is stored as a patch. Unity comparison: like snapping vertices to a surface in ProBuilder, or Blender's Shrinkwrap modifier (project mode) applied. Needs enough points: Divide the shape first. Diagram: `docs/diagrams/shrinkwrap.svg`. Browser test: `e2e/shrinkwrap.spec.ts`.
- **Simplify** (`packages/shared/src/simplify.ts`, `simplifyEditedMesh` in `editOperations.ts`, the Simplify button in `EditModeBar.tsx`): no new library. Quadric edge collapse (Garland and Heckbert): every point carries the sum of its faces' planes, an edge costs how far the merged point would drift from them, and the cheapest edges collapse first (a binary heap, stale entries skipped by version stamps) until about half the triangles are left. Border points never move, so hard edges of shapes built from separate faces survive; collapses that would pinch the surface or fold a face are refused. Drops the UV map, creases and seams. Unity comparison: the LOD generation of Unity's mesh simplifier tools, or Blender's Decimate modifier. Diagram: `docs/diagrams/simplify.svg`. Browser test: `e2e/simplify.spec.ts`.
- **Difference-based undo** (`packages/shared/src/meshPatch.ts`, `apps/web/src/assets/meshStorage.ts`, `commitMesh`, `bytesForFile` in `sceneFileActions.ts`): no new library. An edit of a mesh with 20 000 points or more that only moved points is stored as a "patch" (a small binary: the base mesh id, the numbers of the changed points and their new positions, letters `SRMP`), under the id of the WHOLE new mesh, so a saved file (which always holds whole meshes) still matches. Reading a patch reads its base first (at most 16 patches deep; then a whole mesh is stored again). Big meshes are kept in memory only up to 3 million points (least recently used first) and read again from storage when needed. Unity comparison: like version control storing a diff instead of a copy of the whole file. Browser test: `e2e/bigmesh.spec.ts`.
- **Hide and show** (`packages/shared/src/hiding.ts`, `apps/web/src/meshEdit/hideShow.ts`, `hidden` in `editStore.ts`, the effect in `MeshEditor.tsx`, `buildEditOverlay`): no new library. Hide / Hide others / Show all (H, Shift+H, Alt+H) take triangles out of drawing and picking without changing the mesh; remembered by triangle number with a shape fingerprint, so a tool that changes the triangles shows everything again. Unity comparison: toggling the active state of parts of a mesh in ProBuilder, or Blender's H. Diagram: `docs/diagrams/hide-and-show.svg`. Browser test: `e2e/hide.spec.ts`.
- **UV window editing** (`packages/shared/src/uvEdit.ts`, `transformUvSelection` and `packUvMap` in `editOperations.ts`, `UvWindow.tsx`, `uvSelected` in `editStore.ts`): no new library. Click a piece of the map to choose it (Shift adds), drag to move it (the canvas previews the move; one stored change on release), buttons turn, mirror, scale and Pack. The maths is plain tested functions (`transformUvIslands` moves/turns/scales about the middle of the choice, `packUvIslands` scales all pieces by one factor and shelf-packs them, `uvIslandAt` finds the piece under the pointer); only the map changes, shape and seams stay. Unity comparison: the UV Editor window in Blender or Unity's ProBuilder UV tools. Browser test: `e2e/crate.spec.ts`.
- **Unwrap** (`packages/shared/src/unwrap.ts`, `unwrapMesh` in `editOperations.ts`, `UvWindow.tsx`, `smoothAcrossSplitPoints` in `shapeGeometry.ts`): one-button smart unwrap: charts grown by face direction, planar projection, equal-scale shelf packing by bisection, split points on the cuts, and a read-only UV window drawn on a 2D canvas (no library). Pure and tested (cube: six equal pieces, apart, none flipped; seams respected; angle limit). Unity comparison: Blender's Smart UV Project / ProBuilder's auto UVs. No new libraries.
- **Unwrap along seams** (`packages/shared/src/lscm.ts`, `unwrapMeshAlongSeams` in `editOperations.ts`, the Stretch mode of `UvWindow.tsx`): least squares conformal maps solved with a conjugate gradient written for this project (no linear algebra library), per piece cut by the seams, with a stretch measure per face. Pure and tested (a pipe cut along its length unrolls with no distortion; a cube cut on every edge gives six undistorted pieces; closed pieces are refused). Unity comparison: Blender's Unwrap (Angle Based / Conformal) after Mark Seam. No new libraries.
- **Playwright** (`@playwright/test` 1.65.1, dev dependency; `apps/web/playwright.config.ts`, `apps/web/e2e/`): runs a real Chromium that opens the real editor and clicks through it (home screen, new project, add a cube, Edit points, Divide, Unwrap), checks what is on the page and takes screenshots. Software WebGL (SwiftShader) so the 3D view draws without a graphics card. Run with `pnpm test:e2e` after `export PLAYWRIGHT_BROWSERS_PATH=<folder>`. `apps/web/src/testHooks.ts` is a small seam on `window.__sceneroom` (not in production builds) that lets a test read facts about the mesh and select points by position; the buttons themselves are always clicked for real. A `e2e` job in `.github/workflows/ci.yml` runs them in GitHub Actions. Unity comparison: Play Mode tests / the UI Test Framework, driving the whole game as a player would. The only new library; the browser is kept outside the repo.
- **Zoom to an object** (`FocusController.tsx`, `viewStore.ts`, `packages/shared/src/framing.ts`): double-click a row in the scene list, or press F with objects selected, and the camera glides to the middle of them, keeping its direction, far enough back that they fit (the distance comes from the box round the objects, the camera's field of view and the shape of the view: a pure, tested function). It moves drei's `OrbitControls` target and the camera together; grabbing the camera stops the glide. Unity comparison: Scene view's double-click in the Hierarchy and F. No new libraries.
- **Topology and edge loops** (`packages/shared/src/topology.ts`, `meshEdit/geometryTopology.ts`, `selectionTools.ts`): derived from the plain list of points and triangles and never stored. Points on one spot become a vertex; two flat neighbouring triangles whose shared edge is the longer diagonal become a quad (a face); the edges are the sides of the faces. Edge loops (straight on through four-quad vertices), rings (across quads), picking an edge on the screen, and what a click selects are plain functions, tested on boxes, planes, tubes and the editor's own cube, plane, cylinder and sphere. Edit mode has Points / Edges / Faces (keys 1, 2, 3); edges and faces are selected through their points, so every tool still works on points. Unity comparison: ProBuilder's vertex / edge / face modes and Alt-click loop select. Diagram: `docs/diagrams/edge-loops.svg`. No new libraries.
- **Edit operations** (`packages/shared/src/meshEdit.ts`): `weldGroups` (points on the same spot), `deletePoints`, `extrudeFaces`, `flatFacePoints` and `transformSelected`, all pure functions on typed arrays and tested with exact geometry; the web part (`apps/web/src/meshEdit/editOperations.ts`) runs them on the edited mesh and stores the result as a new version. Alt + click uses a three.js `Raycaster`. No new libraries.
- **Plant generator** (`packages/shared/src/plant.ts`, `apps/web/src/components/viewport/PlantObject.tsx`, `PlantSection.tsx`): a "plant" object holds growth settings and a seed; `generatePlant` grows the wood and leaves as plain typed-array meshes with a small seeded random generator (mulberry32, written by hand), `scatterSpots` and `scatterPlants` make forests, and `bakePlantToMeshes` turns a plant into editable meshes. Drawn with the shared `SurfaceMaterial`. No new libraries.
- **My plants** (`packages/shared/src/plant.ts` for the pure parts, `apps/web/src/store/plantLibraryStore.ts`): saved plants are validated with Zod when read from `localStorage` (`parseCustomPlants` drops what is damaged); `varyPlant` makes the Randomise variations from a seeded random stream. No new libraries.
- **Characters** (`packages/shared/src/character.ts`, `apps/web/src/components/viewport/CharacterObject.tsx`, `CharacterSection.tsx`): a "character" object holds proportions, clothes, colours and a pose; the skeleton is 16 bones as 4x4 matrices written by hand (`boneMatrices`, checked against three.js's own groups), body parts are low-poly meshes built from tubes, blocks and ellipsoids, the view draws nested groups so posing never rebuilds the body, `bakeCharacter` makes editable meshes and the GLB export writes the bone hierarchy. No new libraries.
- **Linked scale**: a link switch beside "Scale" in the Inspector. Linked, changing one of X, Y, Z multiplies the other two by the same factor (`editScaleProportionally`, pure and tested), so the shape keeps its proportions; unlinked, only that value changes. Works for typing, arrow keys and dragging an axis letter. The switch (`scaleLinked`, on by default) lives in `layoutStore.ts` as a screen setting.
- **Model import** (`apps/web/src/assets/`, `ModelObject.tsx`, `ImportButton.tsx`, `ImportBanner.tsx`): a GLB is read by three.js's own `GLTFLoader` (`three/examples/jsm`, no extra package) from memory with `parseAsync`, never from a web address. `SkeletonUtils.clone` gives each object its own copy. The file's fingerprint is a SHA-256 made with the browser's `crypto.subtle`, so the same file is stored once. Files are kept by an `AssetStorage` (in memory for now; IndexedDB comes with saving). The scene holds only a "model" object with an `assetId` and a small record in `scene.assets`. The model shows inside React `Suspense` (a placeholder box while loading) and an error boundary (a red box if it fails). Limits and the header check are pure functions in `packages/shared/src/assets.ts` (tested); the loader is tested with a GLB built by hand.
- **Colour picker**: the colour swatch in the Inspector is a real `<input type="color">`, so clicking it opens the browser's own colour chooser (any colour). Dragging inside it changes the object live (`previewNodeColor`) and is ONE undo step: an edit starts on the first change and ends when the picker closes. The hex box, the quick colours and the reset button still work.
- **Reset buttons**: every changeable value in the Inspector has its own reset button (circular arrow icon) that restores its default in one undo step; see TUNING.md for the list and where each default lives.
- **Materials**: each object has `roughness` and `metalness` (0 to 1, Zod `.min(0).max(1).default(...)`, so older scenes still load), drawn by the standard three.js material (`meshStandardMaterial`). Two sliders with number boxes in the Inspector (`MaterialSlider` in `InspectorFields.tsx`); dragging a slider is one undo step (the same begin / preview / end mechanism as dragging a value). Inputs are cleaned by `sanitizeMaterialChange` and `parseUnitInput` (tested).
- **Gizmo wrapper** (`Gizmo.tsx`): drei `TransformControls` plus a small fix so the move arrows always point away from the object when the gizmo flips to face the camera (a library quirk, see DECISIONS.md). Used by `SelectionGizmo.tsx` and `MultiSelectionGizmo.tsx`.
- **Locking**: each object has a `locked` flag (Zod `.default(false)`, so scenes from before the flag still load). A locked object, or anything inside a locked object, cannot be edited. The rules are enforced in the store (`sceneStore.ts`), not only in the interface, using `isEffectivelyLocked` / `editableIds` (tested). Padlock in the scene list and in the Inspector, key `L`; locked objects let clicks and the selection box pass through.
- **Order of siblings**: each object has an `order` number among the objects that share its parent (Zod `.default(0)`; objects with the same number keep creation order, so older scenes load as before). New objects, imports and pastes go to the end of their parent. In the scene list, the top edge of a row means "before it", the bottom edge "after it" (on an open parent: as its first child), the middle "inside it", with a blue line showing the place; Move up / Move down are in the right-click menu. The rules are pure functions in `packages/shared/src/siblingOrder.ts` (`placeAmongSiblings`, `dropPlacement`, `stepPlacement`, tested); `reparentNodes` takes an optional `beforeId`.
- **Parents and children**: the viewport draws each object INSIDE its parent (`SceneNodes.tsx`, recursive `NodeTree`), so a parent's move, turn and scale carry over to everything in it. Moving an object under another is done by dragging rows in the scene list (`useRowDrag.ts`, pointer events; drop on a row to make a child, or on the bar at the top / the empty space under the rows to make it top-level) or the Parent list in the Inspector. The object keeps its place in the 3D view: its new local transform is worked out from the real three.js objects (`worldTransform.ts`, tested). Rules (no loops, top objects only) are pure functions in `packages/shared/src/reparent.ts`; the store records one undo step.
- **Resizable panels**: `PanelResizer.tsx` is a drag handle (pointer capture, double-click reset, arrow keys, `role="separator"`) on the inner edge of each side panel. Widths live in `layoutStore.ts`, are limited by pure functions in `packages/shared/src/layout.ts` (`clampPanelWidth`, `maxPanelWidth`, tested), and are remembered in `localStorage`, checked with Zod (`parseSavedLayout`).
- **Dragging values**: the X / Y / Z letters in the Inspector are drag handles (`NumberField.tsx`, `scrub`). A drag is wrapped in `beginEdit` / `previewNodeTransform` / `endEdit` in the store, so it is ONE undo step; Escape cancels and restores the old value.
- **Undo / redo**: history is two stacks of earlier states, kept by pure functions in `packages/shared/src/history.ts` (`recordChange`, `undoStep`, `redoStep`, tested). The store (`sceneStore.ts`) records one step before each scene change (gizmo drag = 1 step); selection, gizmo mode and snapping are not undoable; changes that change nothing record nothing. Buttons in `TopBar.tsx`, keys Ctrl/Cmd + Z, Ctrl/Cmd + Shift + Z, Ctrl + Y. Vitest also runs in `apps/web` now (store tests in `src/store/sceneStore.test.ts`).
- **Inspector fields** (`InspectorFields.tsx`, `NumberField.tsx`): Position / Rotation / Scale (X, Y, Z) and a colour hex box with quick swatches, for a single selected object. What you type is checked by pure functions in `packages/shared` (`parseNumberInput`, `editTransform`, `normalizeHexColor`, tested); rotation is typed in degrees and stored in radians. Edits go through the store (`setNodeTransform`, `setNodeColor`), so the gizmo and the fields always agree.
- **Editor shell** (`EditorShell.tsx`): top bar, docked Scene panel (left), 3D view (middle, with `ToolDock` and `ControlsLegend` floating over it), Inspector (right). Colours are Tailwind theme variables in `globals.css` (`bg-ed-panel` and friends); icons are inline SVG in `icons.tsx` (no icon library). `AddMenu.tsx` is a keyboard-friendly pop-up (arrows, Escape, click outside). Layout designed on a Claude design canvas first. Fonts: the existing Geist.
- **Hierarchy panel** (`HierarchyPanel.tsx`, left): the scene as a tree. The tree is built by pure functions in `packages/shared/src/sceneTree.ts` (`buildSceneTree`, `flattenTree`, tested); fold state is UI-only `useState`. Plain Tailwind, no shadcn/ui yet. Hidden objects also stop receiving clicks (`raycast` override in `SceneNodes.tsx`).
- **Multi-select**: the store keeps `selectedIds` (a list). Shift + click toggles one object; Ctrl/Cmd + left-drag draws a box (`BoxSelectController.tsx`) and selects objects whose projected bounding box overlaps it (pure rectangle maths in `packages/shared/src/screenRect.ts`). A pivot object at the group centre carries one `TransformControls`; the pivot's change is applied to every selected object (`MultiSelectionGizmo.tsx`) and written to the store once on mouse up. `meshRegistry.ts` maps node ids to the three.js objects on screen.
- **Object actions**: add / duplicate / delete / rename live in the store and call pure functions in `packages/shared`. Names are checked with Zod (`normalizeNodeName`). UI: `AddToolbar.tsx` (left), `SelectionPanel.tsx` (right, rename/duplicate/delete), shortcuts Delete or Backspace and Ctrl/Cmd + D.
- Scene logic is **pure functions** in `packages/shared/src/sceneOps.ts` (return a new scene, never mutate); the Zustand store only calls them. `pnpm test` runs Vitest through Turborepo and in CI.
