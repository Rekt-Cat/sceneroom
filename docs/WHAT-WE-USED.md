how it works, caveats, why it was chosen, interview questions).

## Settings we changed

- Turborepo and Next.js anonymous telemetry turned off (privacy).
- Next.js "Cache Components" turned off (not needed for this app yet).
- Claude Code **hook** (`PostToolUse`, matcher `Write|Edit`) runs Prettier on files Claude edits inside this project; uses `jq` to read the file path. Lives in `.claude/settings.json`. Needs `/hooks` opened once after the file is first created.
- Claude Code **skill** `/update-what-we-used` (`.claude/skills/update-what-we-used/SKILL.md`) updates this file when something new is added. Needs `/reload-skills` once after the folder is first created.
- The 3D viewport is **browser-only**: `Viewport.tsx` is a Client Component (`"use client"`), loaded by `ViewportLoader.tsx` with `next/dynamic` and `ssr: false`. Next.js only allows `ssr: false` inside a Client Component, so `page.tsx` stays a Server Component.
- Diagrams live in `docs/diagrams/` as self-contained HTML with inline SVG (open in any browser). `dev-workflow.html` (how an edit reaches GitHub) and `architecture.html` (the system, one edit between two users, code layout).
- `create-next-app` generated `AGENTS.md` (notes for coding agents; points to the docs bundled in `node_modules/next/dist/docs/`).

- Git **pre-push hook** (`.husky/pre-push`, via Husky): runs `pnpm check-types && pnpm lint && pnpm test && pnpm build` before every `git push`, including from GitHub Desktop, and blocks the push if one fails. Skip once from a terminal with `git push --no-verify`. `pnpm install` switches it on (root `prepare` script). It adds Homebrew and fnm to `PATH` itself because GitHub Desktop does not load your shell profile.
- **Transform gizmo**: drei `TransformControls` (no new library) on the selected object. It moves the three.js object while you drag and writes the transform to the store once on mouse up (one drag = one change, ready for undo). `OrbitControls` has `makeDefault`, so drei pauses orbiting during a drag. Shortcuts: W / E / R mode, X snap, Esc deselect.
- **Autosave and restore** (`apps/web/src/persistence/`): the scene is saved in the browser's own database, IndexedDB (no library: a small promise wrapper in `idb.ts`), 500 ms after the last change, and restored when the page opens. Imported files go in the same database (`IndexedDbAssetStorage`). What is read back is checked with Zod (`parseSavedScene` in `packages/shared`); unreadable data is copied to a backup first. Saving starts only after the restore has finished. A status ("All changes saved") sits in the top bar and the browser asks before the page is left with unsaved changes. Tested with `fake-indexeddb` 6.2.8 (a dev-only test helper that imitates IndexedDB in Node; Apache-2.0).
- **Copy, cut, paste and the right-click menu**: Copy takes the selected objects and everything inside them as a snapshot (`copyToClipboard`) and Paste makes NEW objects from it (`pasteFromClipboard`: new ids, same structure, numbered names, one step along each time). **Cut only marks** the objects (greyed in the list and faded in the 3D view; a grey wireframe box for imported models); **pasting a cut MOVES the same objects** (`moveToParent`, keeping their place in the 3D view) and empties the clipboard. Where a paste goes is decided by `pasteTarget`: plain Paste = inside the single selected object (`resolveAutoPlacement`; beside it if it is what was copied or cut, top level if nothing is selected), Ctrl/Cmd + Shift + V or "Paste beside" = next to the selected object, "Paste at top level" = top level. Locked parents and pasting an object into itself are refused with a message. Escape cancels a cut. The clipboard is in memory only (not the system clipboard). The menu (`ContextMenu.tsx`) opens on a right-click of an object in the 3D view (a ray from the camera, `ViewportContextMenuController.tsx`) or of a row in the scene list and acts on the selection. `apps/web/vitest.config.ts` lets tests use the `@/` shortcut.
- **Selecting rows in the list**: Shift + click selects the rows between the anchor (the last row clicked, or the only selected object) and the clicked row (`rangeBetween`, pure and tested); Ctrl/Cmd + click adds or removes one row.
- **Assets panel** (the "Assets" tab of the left panel: `AssetsPanel.tsx`, pure rules in `packages/shared/src/assetOps.ts`): lists the imported files of the scene with triangles, size and how many objects use each (`assetUsageCounts`). Place another copy (`placeAsset`), rename the file (`renameAsset`), keep a source / licence note (`setAssetNote`), delete the file together with the objects using it (`removeAsset`, one undo step). Each file has a thumbnail (`apps/web/src/assets/thumbnail.ts`: a plain three.js `WebGLRenderer` draws a copy of the model once into a 128 px picture, `toDataURL`, framing from `thumbnailFraming`) and the whole card can be dragged: dropping it on the 3D view (browser drag and drop, `AssetDropController`, `groundHit`) places the model on the ground at the pointer, with a see-through preview (`AssetPreview.tsx`) while dragging. The rules are pure functions with tests; the store actions only call them and record undo steps. No new libraries.
- **Surface and shading** (`SurfaceSection.tsx`, `materialSchema` in `packages/shared/src/scene.ts`): each object has a `material` section (roughness, metalness, glow colour and strength, opacity, double-sided, flat shading, cast and receive shadow). The Inspector section edits it through `setNodeMaterial` (cleaned by `sanitizeMaterialChange`, undo steps only for real changes); `SceneNodes.tsx` passes the values to three.js's `meshStandardMaterial` and shadow flags. Shadows: `shadows` on the R3F `Canvas`, a shadow-casting directional light and a `shadowMaterial` ground in `Viewport.tsx`. Older saved scenes are migrated by `migrateLegacyMaterial`. No new libraries.
- **Lights** (`packages/shared/src/lights.ts`, `LightObject.tsx`, `LightSection.tsx`): three object kinds (directional, point, spot) with a `light` section. Rendered with three.js's `directionalLight`, `pointLight` and `spotLight` through React Three Fiber; a new light is aimed with `aimRotation` (a small rotation-matrix to Euler conversion, tested). Settings are cleaned by `sanitizeLightChange`; the store has `addLight`, `setNodeLight` and `previewNodeLight` (one undo step per slider drag). The Inspector reuses `ValueSlider` and `ColorRow`. No new libraries.
- **Environment** (`packages/shared/src/environment.ts`, `SceneEnvironment.tsx`, `EnvironmentPanel.tsx`): the world settings live in `scene.environment` (Zod, defaults). `SceneEnvironment` (inside the Canvas) draws the background (a colour, or a canvas-gradient sky as an equirectangular `CanvasTexture`), builds the reflection picture with three.js's `PMREMGenerator` from `RoomEnvironment` (the "studio", `three/examples/jsm/environments/RoomEnvironment.js`) or from the sky texture, and sets fog. Objects read the picture from a small store (`environmentTexture.ts`) to apply their own Reflection strength. The base ambient light and sun read the settings too. No new libraries and no downloads.
- **Modifiers** (`packages/shared/src/modifiers.ts`, `shapeGeometry.ts`, `ModifiersSection.tsx`): each built-in shape has `segments` and a list of modifiers (bend, twist, taper). `deformPoints` (pure maths on plain number arrays, tested) moves the points; `buildShapeGeometry` creates the three.js geometry (`BoxGeometry` etc. with segment counts), applies it with `BufferAttribute`, then `computeVertexNormals`. The store has add, remove, set, preview, move and segment actions (one undo step per slider drag). No new libraries.
- **Linked scale**: a link switch beside "Scale" in the Inspector. Linked, changing one of X, Y, Z multiplies the other two by the same factor (`editScaleProportionally`, pure and tested), so the shape keeps its proportions; unlinked, only that value changes. Works for typing, arrow keys and dragging an axis letter. The switch (`scaleLinked`, on by default) lives in `layoutStore.ts` as a screen setting.
- **Model import** (`apps/web/src/assets/`, `ModelObject.tsx`, `ImportButton.tsx`, `ImportBanner.tsx`): a GLB is read by three.js's own `GLTFLoader` (`three/examples/jsm`, no extra package) from memory with `parseAsync`, never from a web address. `SkeletonUtils.clone` gives each object its own copy. The file's fingerprint is a SHA-256 made with the browser's `crypto.subtle`, so the same file is stored once. Files are kept by an `AssetStorage` (in memory for now; IndexedDB comes with saving). The scene holds only a "model" object with an `assetId` and a small record in `scene.assets`. The model shows inside React `Suspense` (a placeholder box while loading) and an error boundary (a red box if it fails). Limits and the header check are pure functions in `packages/shared/src/assets.ts` (tested); the loader is tested with a GLB built by hand.
- **Colour picker**: the colour swatch in the Inspector is a real `<input type="color">`, so clicking it opens the browser's own colour chooser (any colour). Dragging inside it changes the object live (`previewNodeColor`) and is ONE undo step: an edit starts on the first change and ends when the picker closes. The hex box, the quick colours and the reset button still work.
- **Reset buttons**: every changeable value in the Inspector has its own reset button (circular arrow icon) that restores its default in one undo step; see TUNING.md for the list and where each default lives.
- **Materials**: each object has `roughness` and `metalness` (0 to 1, Zod `.min(0).max(1).default(...)`, so older scenes still load), drawn by the standard three.js material (`meshStandardMaterial`). Two sliders with number boxes in the Inspector (`MaterialSlider` in `InspectorFields.tsx`); dragging a slider is one undo step (the same begin / preview / end mechanism as dragging a value). Inputs are cleaned by `sanitizeMaterialChange` and `parseUnitInput` (tested).
- **Gizmo wrapper** (`Gizmo.tsx`): drei `TransformControls` plus a small fix so the move arrows always point away from the object when the gizmo flips to face the camera (a library quirk, see DECISIONS.md). Used by `SelectionGizmo.tsx` and `MultiSelectionGizmo.tsx`.
- **Locking**: each object has a `locked` flag (Zod `.default(false)`, so scenes from before the flag still load). A locked object, or anything inside a locked object, cannot be edited. The rules are enforced in the store (`sceneStore.ts`), not only in the interface, using `isEffectivelyLocked` / `editableIds` (tested). Padlock in the scene list and in the Inspector, key `L`; locked objects let clicks and the selection box pass through.
- **Order of siblings**: each object has an `order` number among the objects that share its parent (Zod `.default(0)`; objects with the same number keep creation order, so older scenes load as before). New objects, imports and pastes go to the end of their parent. In the scene list, the top edge of a row means "before it", the bottom edge "after it" (on an open parent: as its first child), the middle "inside it", with a blue line showing the place; Move up / Move down are in the right-click menu. The rules are pure functions in `packages/shared/src/siblingOrder.ts` (`placeAmongSiblings`, `dropPlacement`, `stepPlacement`, tested); `reparentNodes` takes an optional `beforeId`.
- **Parents and children**: the viewport draws each object INSIDE its parent (`SceneNodes.tsx`, recursive `NodeTree`), so a parent's move, turn and scale carry over to everything in it. Moving an object under another is done by dragging rows in the scene list (`useRowDrag.ts`, pointer events; drop on a row to make a child, or on the bar at the top / the empty space under the rows to make it top-level) or the Parent list in the Inspector. The object keeps its place in the 3D view: its new local transform is worked out from the real three.js objects (`worldTransform.ts`, tested). Rules (no loops, top objects only) are pure functions in `packages/shared/src/reparent.ts`; the store records one undo step.
- **Resizable panels**: `PanelResizer.tsx` is a drag handle (pointer capture, double-click reset, arrow keys, `role="separator"`) on the inner edge of each side panel. Widths live in `layoutStore.ts`, are limited by pure functions in `packages/shared/src/layout.ts` (`clampPanelWidth`, `maxPanelWidth`, tested), and are remembered in `localStorage`, checked with Zod (`parseSavedLayout`).
- **Dragging values**: the X / Y / Z letters in the Inspector are drag handles (`NumberField.tsx`, `scrub`). A drag is wrapped in `beginEdit` / `previewNodeTransform` / `endEdit` in the store, so it is ONE undo step; Escape cancels and restores the old value.
- **Undo / redo**: history is two stacks of earlier states, kept by pure functions in `packages/shared/src/history.ts` (`recordChange`, `undoStep`, `redoStep`, tested). The store (`sceneStore.ts`) records one step before each scene change (gizmo drag = 1 step); selection, gizmo mode and snapping are not undoable; changes that change nothing record nothing. Buttons in `TopBar.tsx`, keys Ctrl/Cmd + Z, Ctrl/Cmd + Shift + Z, Ctrl + Y. Vitest also runs in `apps/web` now (store tests in `src/store/sceneStore.test.ts`).
- **Inspector fields** (`InspectorFields.tsx`, `NumberField.tsx`): Position / Rotation / Scale (X, Y, Z) and a colour hex box with quick swatches, for a single selected object. What you type is checked by pure functions in `packages/shared` (`parseNumberInput`, `editTransform`, `normalizeHexColor`, tested); rotation is typed in degrees and stored in radians. Edits go through the store (`setNodeTransform`, `setNodeColor`), so the gizmo and the fields always agree.
- **Editor shell** (`EditorShell.tsx`): top bar, docked Scene panel (left), 3D view (middle, with `ToolDock` and `ControlsLegend` floating over it), Inspector (right). Colours are Tailwind theme variables in `globals.css` (`bg-ed-panel` and friends); icons are inline SVG in `icons.tsx` (no icon library). `AddMenu.tsx` is a keyboard-friendly pop-up (arrows, Escape, click outside). Layout designed on a Claude design canvas first. Fonts: the existing Geist.
- **Hierarchy panel** (`HierarchyPanel.tsx`, left): the scene as a tree. The tree is built by pure functions in `packages/shared/src/sceneTree.ts` (`buildSceneTree`, `flattenTree`, tested); fold state is UI-only `useState`. Plain Tailwind, no shadcn/ui yet. Hidden objects also stop receiving clicks (`raycast` override in `SceneNodes.tsx`).
- **Multi-select**: the store keeps `selectedIds` (a list). Shift + click toggles one object; Ctrl/Cmd + left-drag draws a box (`BoxSelectController.tsx`) and selects objects whose projected bounding box overlaps it (pure rectangle maths in `packages/shared/src/screenRect.ts`). A pivot object at the group centre carries one `TransformControls`; the pivot's change is applied to every selected object (`MultiSelectionGizmo.tsx`) and written to the store once on mouse up. `meshRegistry.ts` maps node ids to the three.js objects on screen.
- **Object actions**: add / duplicate / delete / rename live in the store and call pure functions in `packages/shared`. Names are checked with Zod (`normalizeNodeName`). UI: `AddToolbar.tsx` (left), `SelectionPanel.tsx` (right, rename/duplicate/delete), shortcuts Delete or Backspace and Ctrl/Cmd + D.
- Scene logic is **pure functions** in `packages/shared/src/sceneOps.ts` (return a new scene, never mutate); the Zustand store only calls them. `pnpm test` runs Vitest through Turborepo and in CI.
