SceneRoom: script flow

Which scripts run when you open a screen, which run afterwards, and which helper and provider classes they lean on. The figures show the order across the whole app; below them every screen has its own table. Click a box in a figure to jump to the table for that part. File paths are relative to apps/web/src unless they start with packages/ or apps/.

For the parts and how they connect (servers, data, people) see whole-app.html.

Home screen route / (apps/web/src/app/page.tsx)

The list of your projects. Runs entirely in the browser after the page arrives; no server call except the sign-in button.

Runs first, in this order

# Script What it does
1 app/layout.tsx fonts and the <html> shell for every page
2 app/page.tsx returns HomeScreen
3 components/home/HomeScreen.tsx starts in 'loading'; its start-up effect opens the database
4 persistence/idb.ts openDatabase() opens the browser's IndexedDB
5 assets/assetStorage.ts setAssetStorage() from now on imported files are kept in IndexedDB
6 persistence/projectLibrary.ts list() reads the project list; on the very first run moves the old single project in
7 home/ProjectCard.tsx one card per project; its picture comes from library.thumbnail(id)
8 components/home/AccountButton.tsx in parallel: asks /api/auth/get-session who is signed in; shows nothing if accounts are off
9 components/home/OnlineProjects.tsx in parallel: if signed in (fetchMe), lists the projects you are a member of with your role; links open /p/<id>?online=account&scene=<entry scene>

Runs afterwards, when you use it

Script What it does
home/homeActions.ts createNewProject, importProject (.sceneroom file), exportProjectFile; each returns a HomeResult message
persistence/projectLibrary.ts rename, duplicate, delete and save go through the library from the cards
components/viewport/ImportBanner.tsx shows the message of the last action (importStore)
auth/authClient.ts sign in with GitHub / sign out (Better Auth client)
next/navigation router.push('/p/<id>') opening a project leaves this screen for the editor

Helpers, providers and stores it relies on

Script What it does
IndexedDbProjectLibrary class: list, load, save, thumbnail, setThumbnail, rename, delete (the home screen's storage provider)
IndexedDbAssetStorage class implementing AssetStorage over IndexedDB
importStore (Zustand) the one-message bar shared with the editor
authClient Better Auth browser client: useSession, signIn.social, signOut

Editor frame route /p/<projectId> (EditorShell.tsx)

The page around everything else. It starts the saving, the online connection and all the keyboard handling, then lays out the panels.

Runs first, in this order

# Script What it does
1 app/p/[projectId]/page.tsx server side: reads projectId from the address and renders EditorShell

    persistence/startPersistence.ts restore the project, then turn on autosave (see 'Local storage')
    collab/collabController.ts connectCollab() go online if there is a way (see 'Online layer')

Runs afterwards, when you use it

Script What it does

components/viewport/ProjectNotFound.tsx shown instead of the editor when the id is not in this browser
store/persistenceStore.ts 'loading / saved / saving / error / missing' for the top bar
drag and drop handlers a .glb dropped on the 3D view is imported; drops elsewhere are cancelled

Helpers, providers and stores it relies on

useLayoutStore panel widths (saved in localStorage)
importFiles() assets/importFile.ts: checks and imports dropped files

Local storage (save and restore) persistence/ (no server)

Your project is kept in the browser. Restoring comes first; saving starts only after the restore, so the starting cube can never overwrite your project.

Runs first, in this order

# Script What it does
1 persistence/idb.ts openDatabase() IndexedDB wrapper with promises; describeStorageError()
2 persistence/assetStorageIdb.ts IndexedDbAssetStorage: bytes of imported files by SHA-256
3 persistence/projectLibrary.ts load() returns loaded / empty / invalid for this project id
4 store/projectStore.ts loadProject() puts every scene into the stores; opens the active one in sceneStore
5 store/libraryActions.ts applyAllPrefabScenes() applies a prefab edit that was still waiting when the page closed
6 persistence/autosave.ts createAutosave() waits for a quiet moment, then saves; status saving / saved / error
7 components/viewport/thumbnail.ts captureThumbnail() a small picture for the home card

Runs afterwards, when you use it

Script What it does
sceneStore / projectStore subscriptions every change to the scene or the scene list calls autosave.markChanged()
pagehide, visibilitychange, beforeunload flush what is waiting; ask the browser to confirm if something is unsaved
sceneFile/sceneFileActions.ts save to / open a .sceneroom file, with its models and meshes
export/exportGlb.ts, buildExportScene.ts export the scene as a .glb

Helpers, providers and stores it relies on

Script What it does
IndexedDbProjectLibrary the project records
IndexedDbAssetStorage the file bytes
IndexedDbProjectRepository persistence/sceneRepository.ts: implements ProjectRepository from shared/persistence.ts
Autosave (type) markChanged, flush, hasUnsavedChanges, stop

Online layer (in the browser) apps/web/src/collab/

Starts only when a project has a way to go online. It waits for the local restore, then binds the open scene to a shared document.

Runs first, in this order

# Script What it does
1 collabController.ts connectCollab() stops any earlier connection, starts startCollab
2 startCollab.ts waits until persistenceStore says restored; then begin():
    onlineAssetStorage.ts, fileClient.ts, fileUploader.ts wrap the file storage; upload what the scene uses; download what is missing
    collabHistory.ts watchHistory() remembers the scene after each step, for per-person Undo
    collabSession.ts createSceneSession() Y.Doc + sceneBinding + IndexeddbPersistence + HocuspocusProvider (token asked at each connect)
    sceneBinding.ts start(scene): reconcile with the document: seed it or adopt it
    presence.ts, editLocks.ts name, colour, selection, pointer; one editor per object
    objectHolds.ts createObjectHolds() selection locks: publishes your selection as `holding`, works out what the others' holds block, 30 s idle release

Runs afterwards, when you use it

Script What it does
sceneBinding.localChanged / flush diff the scene into the document in one transaction; a viewer's change is put back
sceneBinding pull() someone else's change: readSceneFromDoc (Zod) then sceneStore.applyRemoteScene
fileUploader.request() when the scene's files change
sceneStore.sceneEpoch watcher another scene tab: rebind to that scene's document
tokenSource.ts fresh() at each connect, cached() for files; accounts ask /api/projects/<id>/token
shared/selectiveUndo.ts undoOwnChange / redoOwnChange
objectHolds.ts + blockedByOthers.ts a held object cannot be selected or changed by anyone else: select / toggleSelect / setSelection, isEffectivelyLocked and editableIds, visibility, padlock and reparent all ask isBlockedByOthers
window pointerdown / keydown / wheel any of them counts as activity and restarts the 30 s idle clock

Helpers, providers and stores it relies on

Script What it does
HocuspocusProvider, IndexeddbPersistence, Y.Doc from the libraries: the connection, the offline copy, the shared document
OnlineAssetStorage (AssetStorage) wraps IndexedDbAssetStorage and downloads on demand
TokenSource / fixedToken / createAccountTokenSource where the token comes from
AwarenessLike the small part of awareness the code needs (so it can be tested)

A separate program on port 1234. Starts once; then answers connections and requests.
